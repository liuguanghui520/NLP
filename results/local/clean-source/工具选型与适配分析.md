# 实验监控、自动调参与本地演示工具分析

日期：2026-10-22。适用设备：RTX 4070 Laptop GPU（8188 MiB）、Windows + WSL2 Ubuntu 22.04.5。本文是工程工具分析，不代替个人实验设计及结果分析。

## 1. 推荐组合与职责

建议使用 **LLaMA-Factory/Transformers 训练 + SwanLab 跟踪 + Optuna 自动调参 + Cherry Studio 可选演示**。前三者在 WSL 项目虚拟环境运行，Cherry Studio 在 Windows 运行。现有环境路径为 `/home/lgh/.venvs/llamafactory`，源码为 `/home/lgh/LLaMA-Factory`。

| 工具 | 主要职责 | 优势 | 本项目适配与限制 |
|---|---|---|---|
| SwanLab | 配置、指标、训练曲线和实验比较 | 有中文资料；提供 LLaMA-Factory 与 Transformers 集成；支持离线记录 | 两条训练路径可统一记录；集成导入通过不等于真实训练已验收；不替代逐样本预测和原始日志 |
| Optuna | 根据目标函数搜索参数，可按中间指标剪枝 | Python 接口灵活，支持串行运行、持久化 study | MacBERT 可接 Trainer；LLaMA-Factory 需外层配置生成和结果读取；搜索空间、预算、指标和剪枝规则由本人决定 |
| Cherry Studio | 连接模型服务的交互客户端 | 统一管理服务与模型，便于手动输入评论及演示 | 需要后端服务；不能直接把普通 LoRA 文件当作独立模型运行；聊天记录不能替代批量评估 |
| TensorBoard | 本地训练曲线可视化 | PyTorch 有成熟写入接口，适合已有事件日志 | 与 SwanLab 功能部分重叠；暂不新增安装，避免重复维护 |
| LM Studio | 本地推理、模型管理、API 服务 | 图形界面方便，有 OpenAI 兼容接口 | Windows 演示备选；GGUF 路线增加导出与一致性核验；当前暂不安装 |
| Ollama | 本地模型运行与服务管理 | 命令行工作流清楚，可导入支持的模型格式 | 具体架构和适配器兼容性需实测；不把它当作 LLaMA-Factory 的训练替代；当前暂不安装 |

推荐是依据现有工作流作出的工程判断，不表示这些工具在本项目上已有性能对比结果。

## 2. SwanLab：优先承担实验跟踪

官方提供 LLaMA-Factory 配置入口，以及 Transformers 集成。可以记录 loss、学习率、验证指标和超参数，并比较多个 run。它适合把原始模型、微调模型及不同配置的真实日志集中管理，但只会记录训练程序实际提交的信息。

原始 stdout/stderr、完整配置、模型 revision、数据划分、逐样本原始输出及 OOM 仍应保存在项目目录。显存监控还应结合 PyTorch 的 allocated/reserved 峰值统计；采样得到的设备占用不等于精确的进程内瞬时峰值。

本机版本取舍：安装时 PyPI 提供 SwanLab 0.10.2，但它在 Linux/Python 3.11 下要求 `protobuf>=6.31.1,<7`（排除 6.31.0），现有环境是 `protobuf==7.36.2`。固定现有依赖后，解析器选择 SwanLab 0.6.4；不是安装了最新版。新版本文档中的个别功能未必适用于该旧版，本次只验收实际通过的接口。后续如需要最新版，应在独立环境中验证依赖调整，不能直接照搬新版本配置。

本次验证使用离线模式，不登录账号、不上传课程数据。离线记录、离线可视化服务和云端看板是不同功能；需要本地看板时应按选定版本的官方部署说明配置，不能假定写完离线日志便已有浏览器服务。

## 3. Optuna：优先承担自动调参

Optuna 的每个 trial 对应一次参数尝试。目标函数需要负责模型初始化、训练、验证、返回目标值，以及异常清理。支持 TPE 等搜索算法和中间指标剪枝；这些机制并不保证小预算下必然得到更好结果。

MacBERT 可使用 Transformers 的 `Trainer.hyperparameter_search()`；需要 `model_init`，确保每个 trial 从新模型状态开始。具体 API 应以本机 Transformers 版本为准。LLaMA-Factory 则需要编排程序启动独立配置、读取验证结果并与 trial 对应，安装 Optuna 本身不会让 WebUI 自动调参。

单张 8GB GPU 建议串行执行 trial。持久化 study 时可使用本地 SQLite，日志保留 Optuna trial ID 与项目 run_id 的映射。失败、OOM、剪枝必须分别记录；正式训练不把未完成 trial 当作完整预算结果。调参只读取验证集，最终测试按本人确定的流程执行。

本次仅用数学函数做接口检查，属于软件自检，没有确定或运行课程参数搜索。实验的搜索变量、固定项、范围、预算、成功判据及结论由本人制定。

## 4. Cherry Studio 与推理后端

Cherry Studio 是客户端；LLaMA-Factory、LM Studio 或 Ollama 等提供模型推理服务。计划连接本地服务时，需要配置实际可达的 API URL、模型名和所需鉴权，并验证聊天模板与生成参数。Windows 到 WSL 的访问仍需本机测试。

当前已有 LLaMA-Factory WebUI，可先用于模型加载后的交互验收。Cherry Studio 尚不配置外部 API 密钥，也不下载模型。MacBERT 是分类模型，其 logits/标签通常需要自定义分类接口或专用页面，不应直接按聊天生成模型接入。

若后续采用 GGUF、量化、合并适配器或不同推理引擎，需要单独记录格式、精度、转换过程和版本，并复验输出及指标。训练中的普通 LoRA 与部署时量化是两个维度，不能混称。
