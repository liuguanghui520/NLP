# 项目目录设计与外部路径索引

整理日期：2026-10-23（北京时间）。

本文是项目目录和路径信息的统一维护入口，面向GitHub多人协作。仅为目录设计与路径交接，不代表拟定目录已经创建。本次没有移动文件、创建训练目录、检查环境或执行训练。

## 1. 存放原则

- 本项目文件夹保存方案、分工、数据处理与评估代码、配置归档、结果摘要、报告、演示和外部路径索引。
- 模型训练入口、工具可直接使用的训练配置、训练原始日志、检查点和适配器保留在对应工具的工作目录中，不复制到本项目。
- 预训练模型、分词器和原始数据保留在独立资源目录，不放入Git仓库。
- 不把项目代码写入Python的`site-packages`。Transformers、scikit-learn等只有安装包而没有独立源码工作目录时，为其设置专门的工具工作目录。
- 本项目保存训练配置的冻结副本及校验和，便于GitHub审阅；实际训练读取工具目录中的配置。两份配置必须可核对，不在两边分别手工维护。
- 每次训练使用独立`run_id`目录，失败、恢复和重试均可追溯，旧运行不覆盖。
- 目录变更只更新本文件对应表项及路径登记文件，不在多个说明文档中各自维护不同绝对路径。
- LLaMA-Factory安装位置及其训练工作区由每位协作者在本机配置，不写入共享目录树或共享文档的绝对路径表，不要求所有成员安装到相同位置。

## 2. 本项目目录设计

每位协作者自行克隆仓库。下文统一用`<project_root>`表示本人克隆后的项目根目录，不要求使用同一用户名、磁盘或父目录。

```text
<project_root>
```

使用WSL训练的成员需在本地配置中填写Linux可访问的项目路径；Windows侧路径和WSL侧路径分开登记，不把某位成员的实际路径作为团队统一要求。

目标结构如下，均为规划，不执行现有文件迁移：

```text
NLP/
├── README.md                        # 总入口、执行顺序、路径索引链接
├── AGENTS.md                        # 项目协作规则，保留现有内容
├── 项目目录与路径索引.md             # 本文件：路径信息的专门维护入口
├── docs/
│   ├── design/                      # 实验设计、数据处理方案、三人分工
│   ├── environment/                 # 安装说明、工具选型、版本与本机交接
│   ├── collaboration/               # 对话约定、人工确认与交接记录
│   └── ai-usage/                    # 三人AI使用记录
├── configs/
│   ├── data/                        # 清洗、划分、Alpaca转换配置
│   ├── evaluation/                  # 指标、预测解析与计时规范
│   └── frozen-training/             # 工具端实际使用配置的冻结副本
├── paths/
│   ├── external_paths.example.json  # 可公开的可移植路径模板
│   └── external_paths.local.json    # 本机实际路径；不提交Git
├── scripts/
│   ├── data/                        # 数据分析、转换、核验
│   ├── evaluation/                  # 统一指标、计时汇总、绘图
│   └── orchestration/               # 检查路径、调用工具入口、收集结果索引
├── data/
│   └── processed/<version>/         # 冻结JSONL、Alpaca、ID清单和manifest
├── reports/
│   ├── data/<version>/              # 数据核验报告与统计
│   ├── experiments/                # 参数对照、成本及错误分析
│   └── final/                      # 最终报告与贡献声明
├── results/
│   ├── run_index.jsonl              # 所有外部训练及本地评估运行索引
│   ├── predictions/<run_id>/        # 逐样本预测和推理原始输出
│   ├── metrics/<run_id>/            # 统一重算指标
│   ├── figures/                    # 从真实记录生成的图表
│   └── summaries/                  # 多种子汇总、搜索摘要及失败清单
├── tests/                           # 数据、指标、路径和接口验收
├── demo/                            # 演示说明、客户端配置模板与录屏链接
├── logs/
│   ├── tools-install/              # 保留已有安装证据
│   ├── data/                       # 数据处理日志
│   └── evaluation/                 # 评估及结果收集日志
└── launchers/                       # Windows/WSL启动包装，不包含训练实现
```

根目录现有Markdown、启动脚本和核验脚本暂时保留原位；执行会话如按目标结构迁移，应同步更新引用和启动路径，不删除旧日志。现有`实验设计方案.md`、`分工.md`、`数据处理方案与执行交接.md`等文档以执行时实际文件为准，不凭本设计覆盖同名文件。

## 3. 工具目录内保存训练内容

### 3.1 LLaMA-Factory：Qwen普通LoRA

LLaMA-Factory不作为主仓库目录树的一部分，本文件不规定或列出其本机安装路径和工作区目录树。

每位需要执行LoRA训练的协作者应自行安装或定位该工具，在自己的`paths/external_paths.local.json`中填写：

- `llamafactory_root`：本人LLaMA-Factory安装或源码根目录。
- `lora_workspace`：本人为本项目设置的训练工作区，保留在本人对应工具目录下，并与上游源码文件分离。
- `python_executable`：本人用于调用该工具的Python解释器。

工作区需要保存实际训练配置、数据注册配置、辅助训练脚本、参数对照记录，以及按`run_id`隔离的检查点、最佳适配器、原始日志、SwanLab记录、资源统计和运行manifest。具体绝对位置由本人填写，主项目通过本地配置查找。

不覆盖上游示例配置，不将训练产物提交到LLaMA-Factory上游仓库；检查工具目录的忽略规则，避免误加入大文件。

Alpaca的统一权威数据保留在本项目`data/processed/<version>/alpaca/`。工具的数据注册配置指向实际数据位置；若工具需要工作区副本，标为派生副本并核对SHA256，不重新清洗或划分。

### 3.2 Transformers：随机初始化BERT

Transformers是虚拟环境中的库，不假定存在独立源码仓库。拟定专用工作目录：

```text
<bert_workspace>/
├── scripts/                         # BERT训练、模型初始化及训练回调
├── configs/                         # 4组参数及各训练种子配置
├── studies/                         # Optuna SQLite数据库
└── runs/<run_id>/
    ├── config/
    ├── checkpoints/                # 模型、优化器、调度器及随机状态
    ├── best/                       # 最佳检查点或其指向记录
    ├── logs/
    ├── swanlog/
    ├── resources/
    └── run_manifest.json
```

该目录为拟建的工具工作目录，不是已安装的Transformers包路径。BERT不加载预训练权重，配置及分词器仍从锁定的MacBERT资源目录读取。

### 3.3 scikit-learn：传统基线

拟定专用工作目录：

```text
<tfidf_workspace>/
├── scripts/                         # TF-IDF与逻辑回归拟合入口
├── configs/                         # 6组参数及种子配置
├── studies/                         # Optuna SQLite数据库
└── runs/<run_id>/
    ├── config/
    ├── model/                      # 拟合后的Pipeline
    ├── logs/                       # 收敛警告、log-loss和迭代次数
    ├── swanlog/
    ├── resources/
    └── run_manifest.json
```

传统基线没有神经网络训练检查点，不人为建立loss下降曲线。实际Pipeline序列化文件属于模型产物，留在工具目录。

## 4. 外部路径登记表

共享文档只定义路径键，不登记个人绝对地址。以下实际值均由每位协作者填写到本人不提交Git的本地配置；未知路径保持未配置，不能猜成已存在。

| 路径键 | 本机填写内容 | 用途 |
|---|---|---|
| `project_root_windows` | 本人Windows克隆位置（如使用） | Windows侧项目入口 |
| `project_root_wsl` | 本人Linux/WSL可访问的项目位置 | Linux训练及工具入口 |
| `python_executable` | 本人训练环境的Python解释器 | 不共享虚拟环境绝对路径 |
| `llamafactory_root` | 本人自行填写，不在共享文档登记 | LLaMA-Factory安装或源码根目录 |
| `lora_workspace` | 本人自行填写，不在共享文档登记 | 对应工具目录下的LoRA工作区 |
| `bert_workspace` | 本人自行填写 | Transformers训练工作区 |
| `tfidf_workspace` | 本人自行填写 | scikit-learn拟合工作区 |
| `raw_dataset_root` | 本人原始数据存放目录 | 不修改源文件 |
| `raw_dataset_file` | 本人原始CSV文件地址 | 使用团队锁定SHA256核验 |
| `models_root` | 本人模型资源目录 | 不纳入主仓库 |
| `qwen_model_dir` | 本人Qwen3-1.7B资源地址 | 核对团队锁定revision |
| `macbert_assets_dir` | 本人MacBERT配置和分词器地址 | BERT不读取预训练权重 |
| `processed_dataset_dir` | 本人项目内`data/processed/<version>`的实际地址 | 冻结处理数据 |
| `github_repository` | 待本人提供现有公开仓库URL | 不新建仓库 |

不要把Windows路径直接传给Linux训练程序，也不要把Linux路径直接当成Windows文件路径。WSL发行版名、用户名和磁盘挂载位置由各成员自行确认，不在共享模板写死。

## 5. 本项目如何保留外部训练信息

### 5.1 路径登记文件

后续实现`paths/external_paths.local.json`，登记本机绝对路径、核验时间与状态；模板提交GitHub，本机文件不提交。代码读取路径登记或命令行参数，不散落硬编码绝对路径。

协作者填写流程：

1. 克隆主仓库，复制`external_paths.example.json`为`external_paths.local.json`。
2. 只填写自己负责路线需要的路径；不运行LoRA的成员可将相关键保留为`null`。
3. LLaMA-Factory相关地址填写本人真实位置，不能复制其他成员的本机地址。
4. 启动某条路线时检查其必需路径；未配置则提示填写，不回退到作者电脑路径。
5. 本地配置及个人路径报告加入忽略规则。共享模板仅保留键、`null`占位值和说明，不放个人绝对路径。

以上是后续实现约定，本次没有创建或修改JSON配置和忽略规则。

本文件为人工审阅入口，路径登记文件为程序读取入口。修改路径时两者一起更新；路径未知时使用明确的未登记状态，不填不存在的示例值冒充实际位置。

### 5.2 运行索引

本项目`results/run_index.jsonl`用于可提交的共享运行索引；个人绝对路径另存在不提交Git的本地运行路径映射。每个运行保存：

- `run_id`、路线、种子、阶段（搜索/补充种子/最终评估/冒烟）。
- 运行状态、开始结束时间、失败原因、父运行或恢复来源。
- 工具路径键、相对工作区的运行目录、检查点或适配器相对路径；公开索引不写LLaMA-Factory本机绝对地址。
- 配置、代码、依赖、模型revision及数据manifest的路径和校验和。
- 训练原始日志、SwanLab记录、Optuna study及trial ID。
- 本项目内的预测、指标、图表路径。

共享记录包含执行成员或机器代号及`run_id`，以区分多台机器。本地路径映射以这些标识关联本人绝对位置；其他成员通过模型下载链接或相同源码/配置复现，不依赖访问他人的本地硬盘。

只记录已实际生成的产物。最佳检查点路径与最终恢复后的实际加载路径均须可追溯，不能只记录“best”而不说明对应轮次。

### 5.3 外部训练代码的版本

工具目录中的自定义训练脚本仍需版本管理。执行会话为各工作区建立独立的项目代码版本记录或源码归档，记录提交号/文件SHA256；模型权重、检查点和日志排除在源码版本控制之外。

在主项目记录源码位置、版本与获取方式，必要时提交轻量源码归档或关联源码仓库链接，确保仅拿到主仓库的人也能恢复相同训练入口。不要只留下仅本机可访问的绝对路径就宣称可独立复现。

## 6. 产物归属与GitHub策略

| 内容 | 权威存放位置 | 本项目保留什么 |
|---|---|---|
| 原始评论CSV | 独立数据目录 | 来源、revision、SHA256、读取路径 |
| 处理JSONL、Alpaca和ID清单 | 本项目`data/processed/` | 文件及版本，公开前核实再分发许可 |
| 基座权重、分词器、配置 | 独立模型目录 | 来源、revision、校验和及实际路径 |
| 训练脚本与实际配置 | 对应工具工作区 | 版本索引、可获取源码记录、冻结配置副本 |
| 检查点、适配器、拟合Pipeline | 对应工具运行目录 | 路径、校验和、用途与外部下载链接（如需） |
| 训练原始日志、SwanLab与study | 对应工具工作区 | 路径、关键摘要、导出的可审阅记录 |
| 推理输出、统一指标、图表 | 本项目`results/` | 完整可追溯结果，发布时遵守数据许可 |
| 数据处理及评估日志 | 本项目`logs/` | 每次独立记录 |

公开仓库不提交凭据、本机私有路径配置、虚拟环境、模型权重、批量检查点或工具缓存。数据与含评论原文的预测/报告同样需要许可核验，不因属于结果文件就默认可公开。

## 7. 三人维护职责

- 本人维护训练工具工作区、模型路径、训练配置和运行索引中的训练产物；核对冻结配置副本与实际使用配置一致。
- 成员B维护原始数据及处理版本路径、SHA256、数据manifest与数据核验报告。
- 成员C维护预测、统一评估、图表与演示路径，检查结果能否反查到外部训练运行。
- 每人变更个人绝对路径时只更新自己的本地路径配置和映射；只有路径键、用途或共享布局变化时才更新本文及共享模板。不将个人LLaMA-Factory地址写回共享文档，不擅自迁移他人的产物。

## 8. 执行交接与验收

执行会话按以下顺序落地，不将本文拟定路径视为已创建：

1. 核实现有文件、工具目录和资源位置，登记实际路径及核验时间。
2. 创建必要工作区，保留上游源码和已有产物，不覆盖同名运行。
3. 明确现有文件迁移清单，更新文档、启动器及数据注册配置引用。
4. 建立路径模板、本机路径文件、运行索引和忽略规则。
5. 用路径检查验证读取权限、输出目录及源数据SHA256，不用路径检查代替真实训练验收。
6. 验证主项目能够通过登记路径调用工具入口，并能从运行索引找到配置、日志和模型产物。
7. 从主仓库说明恢复相同源码版本、数据版本与配置，确认不会依赖未说明的本机文件。

验收报告区分“路径已登记”“目录已存在”“读写已核验”“训练已运行”“结果已复现”，不能将这些状态混用。本次设计文档仅完成路径组织方案。
