# 中文评论情感分析：对比实验与错误分析方案

日期：2026-10-28。状态：设计稿；已确认优先使用现有结果，必要补测逐项确认。本文不授权新增训练，不替代学生的人工归因与报告结论。

## 1. 目标、范围与验收对应

回答六个问题：传统模型是否足够有效；预训练编码器与生成式方案的效果差多少；示例与LoRA分别带来什么变化；哪些参数值得选择；各方法主要在哪些评论上失败；取得效果需要多少训练、推理与部署成本。

| 课程要求 | 本方案对应证据 | 完成标准 |
|---|---|---|
| 有基线对比 | 多数类参考、TF-IDF、MacBERT、原始Qwen、LoRA | 主表、配对差异、配置身份可追溯 |
| 指标口径清楚 | 第3节与统一评估代码 | 同一批777条测试数据，非法输出计错，验证与测试分开 |
| ≥3类错误归因 | 人工标注、复核、分类汇总 | 至少3类有真实证据的错误；不能强凑类别 |
| ≥1组参数对比 | BERT学习率、TF-IDF特征、LoRA参数 | 验证指标、配置差异、成本和局限同时呈现 |
| 结论有数据支撑 | 第10节证据台账 | 每条结论关联结果文件、运行和图表 |
| 量化成本延迟 | 第7节 | 训练/搜索/推理分开，P50/P95/均值/吞吐、资源和存储 |

分三层推进：A层仅重算或整理已有证据；B层在现有预测上做新的分组、统计和人工分析；C层涉及真实模型重新推理或训练，须先说明目的、预算、验收，再由本人确认。

## 3. 冻结数据、指标与统计单位

### 3.1 数据和输入

- 固定数据版本v1-20261023，划分种子67；train6210、validation776、test777，不重新划分。
- 标签0=负面、1=正面；验证负244/正532，测试负245/正532。
- 同一sample_id、相同真值和顺序；每个完整测试运行必须777条且ID唯一。
- 共同文本为规范化后的前512个Unicode字符。分别保留原文长度、字符截断、模型token截断、完整提示和示例版本。
- 512字符不等于512token；BERT和Qwen输入预算分别核对，不把相同字符前缀误写为模型看到完全相同的token。
- 少样本正文须由冻结训练示例恢复并核对哈希；带REDACTED的历史注册文件不能直接作为可执行提示。
- 历史基线已使用测试数据，本轮是事后分析；如实披露，不宣称所有假设均在看测试结果前确定。

### 3.2 统一指标

对类别c：TP为该类正确预测，FP为另一真实类误预测成c，FN为真实c但预测另一类或非法输出。

`Precision_c=TP/(TP+FP)`；`Recall_c=TP/(TP+FN)`；`F1_c=2TP/(2TP+FP+FN)`。

`Macro-F1=(F1_0+F1_1)/2`；`Accuracy=正确条数/全部条数`；`Weighted-F1=Σ(support_c×F1_c)/N`。零分母记0。

| 指标 | 用途 | 报告要求 |
|---|---|---|
| Macro-F1 | 唯一主指标、验证选优 | 主表第一列；不简写成含义不明的F1 |
| Accuracy | 辅助整体正确率 | 与类别比例一起解释 |
| 两类Precision/Recall/F1及support | 看负面漏判、正面误判 | 两类均给出，不只报正类 |
| Weighted-F1 | 补充类别加权视角 | 不替代Macro-F1 |
| 非法输出率 | 生成式格式可靠性 | 分母仍为全部样本；非生成路线标不适用 |
| 2×3混淆矩阵 | 分析错误方向 | 行为真实0/1，列为预测0/1/非法；给数量和按行比例 |

生成输出strip后必须精确为0或1；“正面”“答案：1”“1。”均非法。非法不删除、不修成猜测标签；计入Accuracy分母和真实类别FN。不能把非法当第三个真实情感类后计算三类Macro-F1。OOM、缺失预测等基础设施失败阻止完整测试成绩发布，另记运行失败。

主表为测试结果，参数表为验证结果，不把两者混排后排序。BERT/TF-IDF/LoRA逐种子给出单次值、均值、样本标准差（ddof=1）；提示推理不提供虚构的种子标准差。先算每次模型指标再平均，不拼接三份测试记录冒充2331个独立样本，也不默认做投票集成。

原始指标保留0—1尺度和完整精度；展示可用百分比并保留两位小数。差异用百分点：`100×(F1_A−F1_B)`，不能把0.004误写成4个百分点。

### 3.3 不作为主比较的项目

不直接比较BERT分类loss与LoRA答案token loss；不为TF-IDF伪造逐步loss。不增加跨路线不可比的PPL。ROC-AUC/PR-AUC需要可比连续分数；当前生成式仅有离散输出，不强行为全路线填AUC。若日后补概率评估，单独设计并确认。

## 4. 效果、稳定性与配对证据

### 4.1 主结果与样本差异

主结果表包含：方法、配置、训练精度、种子、N、Macro-F1、Accuracy、负面P/R/F1、正面P/R/F1、Weighted-F1、非法率及来源run_id。

配对表对同一条评论统计：均正确、A对B错、A错B对、均错误。分别输出“改善样本”和“退化样本”，不只展示获益案例。训练路线默认用固定seed42展示样本级主对照，43/44作敏感性补充；该规则为当前事后分析选择，不假装预注册，也不按测试成绩挑代表种子。

### 4.2 Macro-F1差异区间（拟新增分析）

建议5000次按真实类别分层的配对bootstrap，固定分析种子67。每次在负、正两类中分别有放回抽取原数量的ID，所有方法、所有种子使用完全相同的抽取索引；先算每个训练种子F1再平均，最后计算方法差值。报告95%百分位区间、重采样次数和分层方式。

该区间反映固定模型、固定类别构成下的测试样本抽样不确定性；不等于训练随机性区间，不能用3个种子准确估计所有训练波动。跨多组的区间是逐项区间，不声称具有整体95%同时覆盖。

### 4.3 正误差异检验

已有精确McNemar及Holm结果保留原比较族与原标签。新增重点七组如需检验，另立清单，固定seed42运行对照，在同一777条上统计正误，非法算错；所有七组统一Holm校正，双侧0.05，并标事后探索性分析。

McNemar回答的是正误/正确率分歧，不是Macro-F1显著性。不能把现有p值标成“F1显著提升”。43/44逐组作为敏感性证据，不把种子展开成独立测试样本。p不显著不代表等效；重点同时报告差值、区间、改善与退化数量。

## 5. 参数对照：充分利用已经执行的实验

使用seed42的lr_1e5、main、lr_5e5（1e-5、2e-5、5e-5）。核对其他设置一致：长度256、3轮、batch16、全参、未加权、相同优化器与调度。按各自验证Macro-F1选择最佳轮次，报告最佳轮次、分数、负面Recall、全程耗时、到最佳检查点耗时（有记录才填）、峰值显存。

## 6. 错例整理、人工标注与局限

### 6.1 候选样本与阅读材料

本人要求：把错例处理为方便人工标注、分析的材料。以测试集正式预测为源，对五路线、三个训练种子的错误按sample_id去重；同一评论只标一遍，保留所有11个运行的预测。用固定分析种子67打乱阅读顺序，不按最精彩案例排序。

本轮已准备首批材料：`results/error-review/review-20261028-v1/review.html`，共402个唯一候选ID、每条保留11个运行；`input_manifest.json`记录12个输入文件SHA256，`candidates.jsonl`保留可重读队列。已检查预测完整性、ID与真值、输出回读、来源哈希和网页脚本语法；未替人标注，未进行浏览器实际交互验收。`scripts/prepare_error_review.py`是材料生成入口，输出目录存在即拒绝覆盖。

提供两种视图：

1. 独立判断视图：评论原文、共同512字符前缀、截断位置、人工整体情感、文本现象和证据；默认隐藏原标签、模型名和模型预测。
2. 对比分析视图：原标签、各运行预测/状态、哪些方法改善或退化、人工主因/次因、可信度和复核结论。

文本标签、错误归因与最终结论均由人填写。自动规则只能提示“含否定词”“字符被截断”等可观察现象，不能自动定论模型失败原因。

共同前缀不等于精确模型token输入。历史缺少实际token截断文本时，仅展示已知长度、截断标志、输入哈希和“无法完整恢复”的说明；null须显示未知，不能冒写未截断。

### 6.2 归因编码表

| 编码 | 类型 | 人工判断依据 | 不能直接推出什么 |
|---|---|---|---|
| E1 | 否定、范围、程度或比较 | 指出否定作用对象、比较对象及整体极性 | 出现“不”不等于因否定而错 |
| E2 | 转折与正负混合、评价对象变化 | 指出正负片段、目标对象和整体判断 | 含“但是”不等于已定位原因 |
| E3 | 隐含情感、反讽与语用 | 指出字面与实际倾向差异、上下文依据 | 无法证明训练分布原因 |
| E4 | 输入信息丢失、长度限制 | 关键情感证据确实在模型不可见部分 | 长文本或截断标志本身不是因果证明 |
| E5 | 生成格式失败 | 原始输出不符合冻结解析规则 | 格式失败不等于语义判断错误 |
| E6 | 标签歧义或疑似数据问题 | 人工与源标签分歧、有文本证据、经复核 | 不直接改测试真值或删除“难例” |
| E7 | 领域表达、短文本或上下文不足 | 明确缺失的酒店语境、指代或隐含要求 | 不能凭错例证明预训练数据缺陷 |
| E8 | 其他或暂无法归因 | 保留观察事实和不确定原因 | 不强迫塞入前三类 |

先标现象，再标与特定模型错误相关的主因；同一评论上不同模型可能有不同主因，特别是格式失败与语义失败。因此采用“样本级文本标注＋样本×运行归因”两层，不能用一个总主因解释所有模型。

建议覆盖至少3个有实际错例的类别，每类至少3个可展示案例，共≥9例；课程最低≥3例作为底线，不预先保证每个候选类别必有案例。优先展示共同失败、LoRA修正提示、LoRA新增错误和BERT/LoRA分歧，兼顾正负真值与长度。

### 6.3 人工工作流

- 准备完整去重候选队列；导出/保存sample_id，人工填写不改变预测文件。
- 人工覆盖范围尚待本人最终确定；完整候选材料不等于承诺已完成全量标注，也不等于已同意双人工作量。
- 本人已确认先试标20条，确认规则后再定覆盖范围；使用固定打乱队列的前20条，ID保存在材料目录的pilot_ids.json，不另挑容易或精彩的条目。建议两人独立判断；具体标注人员尚未确认。修订编码说明并编号版本；规则变更后回标试标条目。
- 正式阶段建议独立标注，第三人处理分歧；保存两人原始判断与最终裁定。若仅一人标注，应如实写明，不能报告双人一致性。
- 可报主类原始一致率和Cohen's kappa；多标签次因逐类给一致性。不用裁定后的结果计算“标注员一致性”。
- 标注字段：sample_id、人工情感、情感证据、现象标签、run_id、主因、次因、归因证据、置信度、疑似标签问题、标注员、日期、规则版本、复核状态、改善建议。
- 错误队列已是按预测筛选的数据，即使隐藏模型也不是随机全测试集盲评；如实说明这种选择限制。

### 6.4 汇总的分母必须明确

1. 某错误类型占比：该模型某类错误数 / 该模型已完成人工归因错误数。主因互斥合计100%，次因多选占比可超过100%。未归因与缺失不能悄悄从完成率里消失。
2. 子群错误率：某现象内该模型错误数 / 该现象全部样本数。要算它，须同样标注正确样本；只看错例无法得出“含否定的评论最难”。
3. 主候选队列含所有种子错误，seed42主分析另取自己的错误集合；43/44作稳定性补充，不把同一评论的多种子错误当独立评论计数。

若暂不标注正确样本，只报告错例内部结构；词表自动检出的否定等分组另标为规则命中，不称人工语义类别。疑似标签问题单列，不修改主测试成绩。

### 6.5 真实案例记录模板

每个案例给出：ID；原文及模型可见部分；源标签与人工解释；五方法seed42原始输出/解析/状态，其他种子是否一致；关键片段；错误主因与证据强度；可能改进；尚未验证的部分。把“观察到什么”“可能原因”“需要什么补测”分开。

如要验证截断因果，可设计同模型同提示仅替换关键可见片段的探索性诊断；这种改输入推理必须另外确认。测试错例指导的改进必须标记使用了测试反馈，不能覆盖原成绩。

## 7. 成本与延迟量化

### 7.1 推理延迟

复用同一固定200条测试ID及顺序，训练集20条预热，batch1、串行、模型已加载。计时含分词、传输、前向/生成、解析；不含磁盘读取和模型加载。GPU前后同步，记录设备、精度、线程、功率/运行状态中已有的观测、输入/输出token和版本。

逐运行报告N、均值、P50、P95、最大值、吞吐。百分位使用linear。吞吐为`N/Σlatency_seconds`，不是逐样本倒数的平均。重复种子分别给出，汇总时“P95均值”必须明确是各次P95再平均，不能称合并分布的P95。

TF-IDF的CPU路线与神经模型GPU路线同时展示设备；这代表本机实际部署方案，不能说是同计算资源下的算法速度排名。既有预算内不强制把所有模型放CPU重测。

生成式同时看生成token数、是否触及8token上限、非法率与慢样本；少样本输入更长但实测更快时，不只用输入长度解释。若历史记录缺生成长度，保留未知，不能捏造原因。

### 7.2 训练与总投入

每路线列出成功搜索、优胜种子42、补充43/44、最终推理/计时、失败/中断/重试、软件检查等阶段。seed42已经包含在搜索成本内，不能再次加总；用run_id唯一去重。原始B00被后续表引用也只计一次。各阶段起止边界和是否含验证/保存都写清。

报告：各次训练总时长、验证时长、到最佳点时长（能取证才填）、搜索总时长、失败重试已知时长；CPU任务小时和GPU占用任务小时按执行设备分组，不能冒称实际CPU核小时或GPU有效计算小时。未训练的提示路线注明项目内训练“不适用”，不能写整体成本为0。

历史分项缺失为null并解释；给已知记录合计时称“已记录成本下界”，不声称完整总成本。不把训练区间、验证子区间、保存时间互相重复相加。B00程序时钟与UTC跨度分别披露。

### 7.3 内存、显存、参数与存储

- 区分PyTorch allocated峰值、reserved峰值和整设备采样显存；注明采样间隔、漏采和错误。
- 当前推理CUDA峰值覆盖加载后测试/预热/基准全过程，只能按该范围命名；历史BERT峰值可能含重载检查，不能当纯训练峰值。
- 当前RSS是期末采样，不冒写进程峰值。新分阶段峰值采集属于待确认补测。
- 总参数、可训练参数及比例；TF-IDF用词表维度和逻辑回归系数数目，不与神经模型参数机械等价。
- LoRA分别给适配器大小、基座大小、完整部署大小；不能拿十几MB适配器与完整BERT模型作部署占用对比。
- 分开统计单模型部署、三个种子归档、全部搜索产物、环境大小（若未测则未知）。共享基座不重复算物理文件，但每个独立部署都需要基座。
- 没有可靠能耗和电价就不报人民币，不把本机算力视为免费。

### 7.4 效果—成本解释

不合成随意加权的“综合得分”。同时展示F1、延迟、训练投入、显存和部署体积，描述观测到的取舍。可画Pareto前沿，但标明设备、统计误差与单次计时局限；只称观测点非支配，不宣称绝对最优。

可将均值延迟换算串行10000条的估计耗时：`10000×mean_ms/1000`秒；必须标估算、不含加载，不伪装真实整批运行。不跨设备算“每GPU小时性价比”。

## 8. 子群、稳定性与泛化限制

仅使用现有预测即可新增以下分析：

| 子群 | 固定规则 | 输出 |
|---|---|---|
| 真实类别 | 负/正 | support、P/R/F1、漏判方向 |
| 原始规范化长度 | 1—50、51—128、129—256、257—512、>512字符 | N、错误数、Accuracy、Macro-F1、类别构成 |
| 字符截断 | 否/是 | 各方法错误数和差异 |
| 模型token截断 | 每路线单独，是/否/未知 | 不把各路线的不同子群当同一批样本比较 |
| 种子一致性 | 训练方法内0/1/2/3次出错 | 每条评论的稳定失败与波动 |
| 规则命中（补充） | 冻结否定/转折词表版本 | 仅称词表命中子群，不替代人工归因 |

所有长度分箱在计算前固定，不根据哪个箱差异大再改边界。N<30或缺任一真实类别时，明确小样本/单类限制；这是保守展示规则，不是统计保证。保留两类F1零除约定，但不把单类子群Macro-F1用于方法排名。

泛化局限至少讨论：酒店评论单领域；仅一个固定划分；类别不均衡；原始前缀截断；只选一组少样本示例；多数参数单种子；预训练与提示格式差异；本机笔记本计时及历史记录缺失；已查看测试集的事后分析。每项连接到实际数据或实验边界，不虚构已验证的跨领域失败。
