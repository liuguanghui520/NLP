## 参数含义与工程影响

| 参数 | 控制内容 | 修改时需记录的联动与限制 |
|---|---|---|
| learning_rate | 参数更新步长 | 记录初始值及调度曲线，保持优化器、预热规则与批量口径明确 |
| lora_rank | 低秩更新维度 | 影响可训练参数量及适配器大小，实际显存/时间需测量 |
| lora_alpha | 标准LoRA的缩放系数 | 标准LoRA缩放为alpha/r；既定方案alpha=2r。若启用rsLoRA缩放规则会改变，不能混入同一设置 |
| lora_dropout | LoRA分支的dropout | 保持样本、训练长度、种子口径可比较；效果由真实验证判断 |
| lora_target | 注入LoRA的模块 | 需要核对模型真实模块名；改变模块也改变适配器参数量和资源需求 |
| weight_decay | 优化器权重衰减 | 与dropout属于不同机制，不能把它们作为同一个参数记录 |
| num_train_epochs | 训练数据遍历轮数 | 与总更新步数、每轮验证、最佳检查点选择相联系；max_steps非默认限制可能覆盖轮数 |
| warmup_ratio / warmup_steps | 预热长度 | 比较时明确采用比例还是固定步数，不同时遗留互相覆盖的设置 |
| lr_scheduler_type | 学习率随训练推进的变化方式 | 如比较该项，需保存真实学习率曲线 |
| 有效批量 | 每次更新累计处理的样本量 | 单GPU有效批量=微批量×梯度累积；增大累积与增大微批量的显存影响不同 |

随机种子属于重复运行设置，不作为按验证集挑选的优化目标。精度、量化、模型大小及提示示例数分别涉及数值表示、训练方案、模型或推理设置，若改变应单独命名与记录。

## 组合预算核算

若对选中的参数做全部组合，组数为每个参数候选数的乘积。以下只演示乘法，不指定实际取值或推荐实验组：

- 两个变量各有2、3个候选：2×3=6组。
- 再加入2个候选的第三变量：2×3×2=12组。
- 再加入2个候选的第四变量：2×3×2×2=24组。

如果首轮每组运行种子42，只有最终优胜组补43、44，则LoRA训练数为首轮组数+2；若每组都做3个种子，则为首轮组数×3。两者提供的稳定性证据范围不同，需本人选择，不能混称。

每次训练成本还包含逐轮分类验证。预算可写为各运行的训练耗时与验证耗时之和，再加基座提示推理、最终评估、资源测量和失败重试。0.6B的20步体验耗时不能作为1.7B全量训练的直接估算。
