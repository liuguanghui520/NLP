一、项目定位

用一条完整的小型 NLP 流水线，把课程里学过的方法真正用起来：数据 → 方法 → 评估 → 错误分析。

外壳是大模型应用，内核是课程方法：每个项目都必须包含 ① 一个非大模型基线　② 一个大模型方案　③ 两者的对比评估。

评分不看模型多大，只看四件事：有没有基线对比、有没有评估数据、有没有把失败讲清楚、别人能不能复现。

一句话：用 7B 模型 + 完整评估 + 诚实分析，得分会高于用 70B 模型但只给一个分数的项目。

二、选题方向（四选一）

方向大模型方案参考基线（考课程前段）主要覆盖讲次
A. 领域 RAG 问答检索 + 提示约束 + 引用校验关键词 / BM25 检索、词向量平均检索，与向量检索对比2、5、14、15
B. 信息抽取 / 序列标注LLM 提示抽取，或 BERT 微调（逐位置分类，可接 CRF）规则 / 词典基线 + 小模型；逐 token 指标与实体级 P/R/F1 对比6、9、12
C. 提示 vs 微调对比零样本 / 少样本提示、LoRA 轻量微调TF-IDF、n-gram 或小模型全参微调5、7、12、13
D. 大模型评测幻觉检测、鲁棒性测试、指标设计传统指标（P/R/F1、BLEU/ROUGE）的局限实证6、10、14、15

说明：

  1. 鼓励结合学院特色方向：金融科技（上市公司公告、研报问答、公告要素抽取）、智慧健康（医学知识问答、病历要素抽取）。
  2. 也可以自选题目，但选题确认时必须写清：问题定义、成功判据、与课程方法的对应关系。

三、每个项目必须回答的 3 个原理点

报告中必须用自己实验的证据解释至少 3 个课程原理点（只复述概念不算，必须给出实验或数据支撑）：

  1. 分词 / 子词与词表选择对检索或抽取效果的影响（第 2 讲）
  2. 词向量与句向量的表示能力差异（第 5 讲）
  3. N-gram 与神经网络语言模型的取舍、困惑度（PPL）与生成质量的关系（第 7—8 讲）
  4. 序列标注的标签约束与实体级评测口径（第 9 讲）
  5. 注意力机制为什么能缓解信息瓶颈（第 10 讲）
  6. Transformer 的位置编码、缩放点积与复杂度取舍（第 11 讲）
  7. 预训练目标（AR 与 MLM）对下游任务的影响（第 12 讲）
  8. SFT / LoRA / 提示的本质差别与适用边界（第 13—14 讲）
  9. RAG 的"召回是上限"、重排与引用校验的作用（第 15 讲）
  10. 评测指标与评测协议的选择依据（第 14—15 讲）

四、数据与工具

  1. 数据优先用公开数据，并在报告中写明来源、规模、许可与清洗规则。可参考（使用前请自行确认许可与下载可用性）：中文新闻分类（THUCNews）、情感分析（ChnSentiCorp）、中文 NER（MSRA、人民日报、CLUENER2020）、中文阅读理解（CMRC2018）、医学与健康方向（CBLUE 类基准任务）、英文（SQuAD 等）。金融方向可自行从公开披露渠道（如上市公司公告）构造数据。
  2. 允许调用外部 API（这是本课程的工程现实），但必须做到：
    • 费用自负，报告里写明所用模型、调用量、单价与总花费估算；
    • API Key 一律不得写进代码或提交到仓库（用环境变量），提交前自查；
    • 不得把隐私数据、未授权的个人数据上传给任何外部服务；医学、金融数据必须脱敏。
  3. 允许本地小模型 / CPU 方案：预算或算力受限的小组，可缩小数据规模，只要在报告中说明降级原因与影响即可，不因此扣分。
  4. 允许使用 AI 辅助（边界见第九节），但报告必须附AI 使用声明。

  1. 跑不通 = 项目不及格：教师或 AI 按 README 无法复现主结果的，允许 48 小时内补交环境说明或修复；补交后仍无法跑通的，第 ③ 项记 0 分，总分不超过 25 分。
  2. 报告与代码/日志对不上：报告中的关键数字在代码、日志或输出文件中找不到出处的，第 ④ 项减半；编造实验数据按学术不诚信处理。

三个拉开分差的地方

  • 主动写出失败案例与局限（≥3 个，逐一归因）；
  • 有参数对比实验并给出结论（如 top-k、chunk 大小、LoRA 秩、不同模型）；
  • 能说清成本与延迟（token 花费、响应时间），而不是只说"效果好"。
