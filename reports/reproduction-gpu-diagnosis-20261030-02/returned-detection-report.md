## 结论

**诊断工具与输入完整，三配置在本机全部完成，正式结果没有被修改。**

本轮可以确认的是：

- 4070 与 4060 的 16/16 输入 token ID 一致，模型文件哈希、数值 buffer 指纹和除设备信息外的运行时字段一致。
- 4060 原路径与 4070 原路径的 16 条验证诊断仅 1 条原始输出不同，但 16 条首步 score tensor 哈希全部不同。
- 唯一输出分歧位于 `qwen_zero_shot` 验证样本尾号 `5500`，并在第一个生成 token 就发生。
- 首步前两名 token 在该样本上分别只相差 0.25（4070 原路径）和 0.25（4060 原路径），排名从 token 16 变为 token 15。
- 4060 的两轮独立运行在三个配置上均是 16/16 输入、生成 token、首步得分哈希和全部逐步得分一致，说明本机结果是可重复的，不是偶发噪声。
- `controlled_flash` 与 `controlled_math` 都把首步得分不同的样本数从 16 降到 14，但仍各有 1/16 输出不同，尚不能作为完整修复。

不能确认的是：具体由哪一个 GPU 内核、驱动版本、SM 数量或硬件调度导致这些数值差异。当前证据能定位到 BF16 推理的首步数值得分和低分差排序变化，但不能唯一归因。小样本诊断没有改变此前正式 11×777 的 `completed_with_differences` 结论。

## 唯一样本分歧

样本：

```text
method: qwen_zero_shot
sample_id: 1d414b9c65caf3a836abdb4efded621968502ad3338e1a9d885ae131c86083f0:5500
true_label: 0
first_different_generated_step: 0
```

| 项目 | 4070 原路径 | 4060 原路径 |
|---|---|---|
| 首 token | `16` | `15` |
| 首步 top-1 分数 | 36.5 | 35.75 |
| 首步 top-2 分数 | 36.25 | 35.5 |
| 首步前两名差值 | 0.25 | 0.25 |
| 原始输出 | `1` | `0\n\n说明：评论整体表达了强烈的` |
| 严格解析标签 | 1 | 非法 `null` |

该样本在历史冻结验证预测中原本也是未解析文本；因此 4060 原路径虽然保留了 `parsed_label=None`，但原始文本与历史不同。不能把它简单描述为“4060 复现了历史，4070 出错”。

受控配置在同一首 token 上也发生了分歧：

- `controlled_flash`：4070 token `100345`，4060 token `16`。
- `controlled_math`：4070 token `15`，4060 token `16`。
